# Luma 0.2.0

Luma — небольшой динамически типизированный язык и компилятор на C++17.
Он предназначен для изучения устройства языков и небольших консольных программ.
Исходник можно выполнить интерпретатором, скомпилировать в байткод для VM
или сохранить как `.lbc`. Это не компилятор в самостоятельный native executable.

Философия: небольшой язык, явные объявления, простые правила и библиотека
преимущественно на самой Luma. Статус — первый публичный выпуск 0.2.0,
ранняя реализация: долгосрочная стабильность API и формата байткода не гарантируется.

## Возможности

- Числа, строки, boolean, nil, массивы и функции-значения.
- Лексические области, замыкания, рекурсия, условия и циклы.
- `import "module.luma"` с относительными и вложенными импортами.
- Консольный ввод, 8 обычных builtins и 3 низкоуровневых native primitives.
- Четыре stdlib-модуля: math, string, random, io; 19 публичных Luma-функций.
- Интерпретатор и стековая VM, файлы байткода, диагностика и валидация `.lbc`.

## Сборка на Windows

Скачайте исходники репозитория и распакуйте их. Нужен MinGW-w64 `g++`
с поддержкой C++17 и статической линковки, доступный в `PATH`.
Проверенная среда — Windows, PowerShell и MinGW-w64. Готового установщика,
package manager или проверенной инструкции сборки для Linux/macOS в проекте нет.

Откройте PowerShell **в корне распакованного проекта**, где находится `build.bat`:

```powershell
g++ --version
.\build.bat
.\luma.exe --version
```

Сборка создаёт `luma.exe` и `tests/run_tests.exe`; дополнительных библиотек
Luma не требует. Если `g++` не найден, исправьте `PATH` и откройте новую консоль.
Путь может содержать пробелы: `Set-Location -LiteralPath 'D:\L Compiler'` —
пример, а не обязательное расположение проекта. Сохранённые файлы `.luma`
должны быть UTF-8 без BOM.

## Quick Start

1. Соберите проект командой выше.
2. Создайте в корне `hello.luma`:

```luma
print("Hello, Luma!")
let numbers = [10,20,30]
let total = 0
for i in 0..len(numbers) do
    total = total + numbers[i]
end
print(total)
```

3. Выполните, скомпилируйте и запустите артефакт:

```powershell
.\luma.exe vm hello.luma
.\luma.exe compile hello.luma hello.lbc
.\luma.exe execute hello.lbc
```

Вывод: `Hello, Luma!`, затем `60`.
Альтернативный бэкенд: `.\luma.exe run hello.luma`.

## CLI

Все команды ниже выполняются из корня проекта:

| Команда | Назначение |
| --- | --- |
| `.\luma.exe run examples\hello.luma` | Исполнение AST интерпретатором |
| `.\luma.exe vm examples\hello.luma` | Компиляция и запуск на VM |
| `.\luma.exe examples\hello.luma` | Неявный запуск на VM |
| `.\luma.exe compile examples\hello.luma hello.lbc` | Создание артефакта |
| `.\luma.exe execute hello.lbc` | Запуск артефакта |
| `.\luma.exe hello.lbc` | Неявный запуск артефакта |
| `.\luma.exe bytecode hello.lbc` | Дизассемблирование |
| `.\luma.exe --help` | Справка |
| `.\luma.exe --version` | Версия |

Также существуют `tokens`, `ast`, `eval` и `bytecode` для исходников.
Полные аргументы, ограничения и коды выхода — в [CLI](docs/CLI.md).
REPL нет: запуск без аргументов показывает usage и возвращает код 64.

## Импорты и стандартная библиотека

Сохраните следующую программу как `dice.luma` **в корне проекта**:

<!-- luma-check: root -->
```luma
import "stdlib/math.luma"
import "stdlib/string.luma"
import "stdlib/random.luma"
random_seed(123)
print(join(["Luma","dice"], " "))
print(clamp(random_range(1,6),2,5))
```

Запуск: `.\luma.exe vm dice.luma`. Пути считаются относительно
**импортирующего файла**, а не консоли: из `examples/` нужен
`import "../stdlib/math.luma"`. Модули не загружаются автоматически.
Импорт разворачивается до анализа; объявления попадают в общую глобальную область.
Повторный canonical path загружается один раз. Циклы и конфликты имён — ошибки.
После компиляции подключённый Luma-код находится в `.lbc`;
для исполнения исходные модули не нужны, но нужен совместимый runtime.

Демонстрация всех четырёх модулей:

```powershell
.\luma.exe vm examples\stdlib_demo.luma
```

Введите имя, затем целочисленный seed, например `1`.

## Известные ограничения

- Строки — байты, не Unicode-символы; `substr` может разрезать UTF-8.
- Нет namespaces/exports, maps, классов, анонимных функций или обработки исключений в языке.
- Дробные индексы массивов усекаются после проверки границ; используйте целые.
- RNG воспроизводимый, не криптографический; IO только консольный.
- Нет GC: циклы ссылок могут удерживать память. Нет sandbox, тайм-лимита или общего лимита памяти.
- Для глубокой рекурсии предпочтительна VM; рекурсивный `run` ограничен стеком C++.
- `.lbc` — внутренний формат, не самостоятельная программа и не обещание вечной совместимости.
- Новые builtin-имена 0.2.0 заняты в глобальной области; старые одноимённые объявления конфликтуют.
