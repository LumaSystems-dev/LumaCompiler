# Артефакты .lbc

[Индекс](README.md) · [CLI](CLI.md) · [архитектура](../DESIGN.md).

`.lbc` — бинарный артефакт компиляции Luma, не native executable.
Он содержит инструкции VM, константы, прототипы функций и номера строк.
Верхнеуровневые значения и состояние RNG/input заново создаются при запуске;
это не snapshot памяти процесса.

## Создание и исполнение

Из корня проекта:

```powershell
.\luma.exe compile examples\hello.luma hello.lbc
.\luma.exe execute hello.lbc
.\luma.exe bytecode hello.lbc
```

Без output compile пишет рядом с исходником, заменяя расширение на .lbc.
Используйте отдельное имя: output перезаписывается.
`.\luma.exe hello.lbc` эквивалентно execute.

Импорты разворачиваются до анализа и компиляции. Библиотечные функции находятся
в артефакте, поэтому исходник и подключённые модули не нужны для execute.
Но builtins предоставляются runtime при запуске: для primitives stdlib 0.2.0
используйте Luma 0.2.0. Артефакт не включает сам runtime.
input по-прежнему читает stdin запускающего процесса.

## Что проверяется

Загрузчик проверяет сигнатуру/версию формата, достаточность данных,
размеры секций, теги констант и отсутствие лишних данных.
Ограничения применяются **до** крупных выделений памяти.
Затем validator проверяет инструкции и операнды, индексы/типы констант,
границы переходов, стек и глубины областей на достижимых путях.
Прототипы функций проверяются рекурсивно, даже если не вызываются.
VM также валидирует Chunk на входе; Compiler не является единственным
допустимым источником объектов Chunk для C++ кода.

Повреждённый файл завершается ошибкой/кодом 65, например:

```text
Error: not a Luma bytecode file (bad magic)
Error: unsupported Luma bytecode format version
Error: corrupted bytecode file: unexpected end
Error: corrupted bytecode: unknown opcode at offset 0
```

Восстановите исходники и скомпилируйте заново; вручную править файл не рекомендуется.
Валидация не доказывает корректность бизнес-логики и не является подписью,
шифрованием или sandbox. Валидная программа может зависнуть или расходовать память.
Не запускайте недоверенные артефакты в надежде на изоляцию.

## Диагностика, ограничения и совместимость

Номера строк сохраняются, исходный текст, колонки и пути модулей — нет.
Runtime-ошибка при execute может назвать номер строки, но не показать
соответствующий источник. Для отладки храните исходники отдельно.

Загрузчик ограничивает одну секцию кода 16 MiB, одну строковую константу
8 MiB, вложенность прототипов 128. Бюджет 64 MiB учитывает не только
байты файла, но и часть памяти создаваемых структур; это **не** обещание
принимать любой файл размером до 64 MiB. Валидация ограничивает глубину
областей одного чанка 128. VM имеет отдельные лимиты исполнения; см. DESIGN.
Размеры отдельных конструкций также ограничены 16-битными операндами.

Текущая сигнатура — три байта `LBC` и байт версии `0x01`.
Версия формата не совпадает с версией языка 0.2.0. Формат в 0.2.0 не менялся,
но остаётся внутренним и может измениться в будущем; стабильного SDK/ABI нет.
Прежние артефакты не получают исправления Compiler автоматически:
для исправленной генерации сравнений с NaN пересоберите исходник текущим компилятором.
Для release сохраняйте source и указывайте версию runtime вместе с артефактом.
