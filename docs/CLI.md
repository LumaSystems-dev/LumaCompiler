# CLI Luma 0.2.0

[Индекс](README.md). Команды показывают PowerShell из корня проекта.
`luma` в описаниях означает `.\luma.exe`; добавление в PATH необязательно.
Пути с пробелами заключайте в двойные кавычки.
Явные команды принимают путь к файлу, не исходный текст и не stdin-программу.
Неизвестные флаги и лишние аргументы не поддерживаются.

## Исполнение

| Синтаксис | Назначение / аргументы | Пример |
| --- | --- | --- |
| `luma run <source>` | Один исходник; lexer/parser/import/analyzer, затем AST Interpreter | `.\luma.exe run examples\hello.luma` |
| `luma vm <source>` | Один исходник; тот же frontend, Compiler → VM | `.\luma.exe vm examples\hello.luma` |
| `luma <file.luma>` | Неявный vm; требуется суффикс .luma | `.\luma.exe examples\hello.luma` |
| `luma execute <artifact>` | Один бинарный артефакт, loader/validator → VM | `.\luma.exe execute hello.lbc` |
| `luma <file.lbc>` | Неявный execute; требуется суффикс .lbc | `.\luma.exe hello.lbc` |

Автоматическое определение расширения чувствительно к регистру: используйте
нижний регистр. У явных run/vm нет обязательной проверки расширения,
но содержимое должно быть исходником. execute всегда читает бинарный формат.
Типичные ошибки: недоступный файл (66), ошибка синтаксиса/анализа/runtime
или некорректный артефакт (65). input читает stdin во время исполнения.
В отличие от VM, run не рассчитан на очень глубокую рекурсию.

## Компиляция

`luma compile <source> [output]`: один исходник и необязательный путь артефакта.
По умолчанию последнее расширение входного имени заменяется на `.lbc`;
без расширения суффикс добавляется. Существующий output **перезаписывается**.
Не используйте исходный файл как output. Каталоги автоматически не создаются.
После успеха выводится `compiled ... -> ...`.
Недоступный output — 66; ошибки frontend, лимитов, записи — 65.

```powershell
.\luma.exe compile examples\hello.luma hello.lbc
.\luma.exe execute hello.lbc
```

Compile не исполняет верхнеуровневый код и не читает input.
Для распространения нужны артефакт и совместимый luma runtime.
Подробнее — [Bytecode](BYTECODE.md).

## Диагностические команды

| Синтаксис | Назначение / аргументы | Пример |
| --- | --- | --- |
| `luma tokens <source>` | Один исходник; печать токенов без import/Analyzer | `.\luma.exe tokens examples\lex_demo.luma` |
| `luma ast <source>` | Один исходник; дерево разбора, без import/Analyzer | `.\luma.exe ast examples\ast_demo.luma` |
| `luma bytecode <source\|artifact.lbc>` | Один файл; .lbc загружается, другой суффикс компилируется как source; код не исполняется | `.\luma.exe bytecode examples\bytecode_demo.luma` |
| `luma eval <source>` | Один файл с **единственным выражением**, AST eval без import/Analyzer | `.\luma.exe eval examples\eval_demo.luma` |

tokens/ast могут работать с программой, которую Analyzer отвергнет.
eval — не REPL, не принимает `let`, инструкции или завершающий `;`;
builtins доступны, пользовательских объявлений в его файле нет.
Ошибка lexer/parser/eval/валидации — 65, недоступный файл — 66.
AST printer — отладочная визуализация, не стабильный машинный формат:
некоторые узлы/метаданные отображаются неполно.
bytecode выводит внутренние offsets, opcodes, constants и прототипы;
его текст не является входным форматом компилятора.

## Справка, версия и отсутствие команды

| Синтаксис | Поведение | Пример |
| --- | --- | --- |
| `luma --help`, `luma -h` | Usage в stderr, код 0; без дополнительных аргументов | `.\luma.exe --help` |
| `luma --version`, `luma -v` | `Luma 0.2.0` в stdout, код 0 | `.\luma.exe --version` |
| `luma` | Usage в stderr, код 64; интерактивного режима нет | `.\luma.exe` |

Неверное количество аргументов — usage/64. Неизвестная одиночная команда
или неподдержанный суффикс — `Unknown command or unsupported file`/64.

## Workflow и диагностика

```text
.luma + imported .luma → frontend → compile → .lbc → loader/validator → execute → VM
```

Исходник нужен во время compile; импортированные исходники встраиваются как код.
Для execute они не обязательны; диагностика артефакта менее подробна.

| Код | Значение |
| --- | --- |
| 0 | Успех |
| 64 | Неправильный CLI-вызов |
| 65 | Ошибка языка, runtime, import, артефакта или пойманное исключение |
| 66 | Нельзя открыть главный входной/выходной файл |

Отсутствующий импорт — 65, не 66. Сообщения идут в stderr.
Для исходника доступные файл/строка/байтовая колонка выводятся перед
`Error at line N: ...`; для ошибок без строки — `Error: ...`.
Runtime-ошибки в импортированном коде пока не имеют полной карты исходных файлов.
Остановка через Ctrl+C — средство консоли, не конструкция Luma.
