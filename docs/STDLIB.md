# Стандартная библиотека Luma 0.2.0

Модули — обычные `.luma`-файлы, которые импортируются существующим resolver.
Из программы в `examples/`:

```luma
import "../stdlib/math.luma"
import "../stdlib/string.luma"
import "../stdlib/random.luma"
import "../stdlib/io.luma"
```

Путь всегда относительно импортирующего файла. Специального поиска stdlib,
автозагрузки, namespaces и exports нет. Один файл с одинаковым canonical path
загружается один раз; объявления попадают в общую глобальную область.
Повторные импорты не сбрасывают seed. Конфликт имён — ошибка Analyzer.
Скомпилированный `.lbc` содержит библиотечный код и не требует исходных модулей;
для новых native primitives нужен runtime Luma 0.2.0.

## math.luma

Все аргументы должны быть конечными числами. Типы не преобразуются автоматически.

| API | Результат и ограничения |
| --- | --- |
| `abs(value)` | Модуль числа; `abs(-3)` → `3`. |
| `min(a, b)` | Меньшее из двух чисел. |
| `max(a, b)` | Большее из двух чисел. |
| `clamp(value, lower, upper)` | Ограничивает число замкнутым диапазоном; `lower > upper` — ошибка. |
| `pow(base, exponent)` | Степень, включая отрицательные/дробные показатели; результат должен принадлежать конечным вещественным числам. `pow(0,0)` → `1`; `pow(-1,0.5)` и переполнение — ошибки; underflow до `0` допустим. |
| `sqrt(value)` | Квадратный корень; отрицательное число — ошибка, `sqrt(0)` → `0`. |

`abs`, `min`, `max`, `clamp` и `_math_finite` написаны на Luma. `pow` и
`sqrt` — Luma-обёртки над `_luma_pow`/`_luma_sqrt` (`std::pow`/`std::sqrt`),
чтобы не воспроизводить численные алгоритмы приближёнными циклами.

## string.luma

Строки остаются последовательностями байтов UTF-8. Все параметры текста — строки;
числа, массивы и другие типы явно отклоняются.

| API | Результат и ограничения |
| --- | --- |
| `string_length(text)` | Число байтов; `string_length("Лума")` → `8`. |
| `substr(text, start, count)` | `count` байтов с позиции `start`. Нумерация с нуля; параметры конечные неотрицательные целые; весь диапазон обязан находиться в строке. `substr("abc",3,0)` → `""`. |
| `find(text, needle)` | Позиция первого вхождения в байтах либо `-1`. Пустая искомая строка найдена на позиции `0`. |
| `contains(text, needle)` | Boolean: есть ли вхождение. |
| `starts_with(text, prefix)` | Boolean; пустой prefix всегда совпадает. |
| `ends_with(text, suffix)` | Boolean; пустой suffix всегда совпадает. |
| `trim(text)` | Удаляет с краёв ASCII-пробел, TAB, CR и LF; внутренние пробелы сохраняются. |
| `join(parts, separator)` | Соединяет массив строк; `join([], ",")` → `""`. Не меняет массив; не преобразует элементы в строки автоматически. |

Алгоритмы поиска, проверок, обрезки и соединения реализованы на Luma. Только
`substr` вызывает native `_luma_slice`: существующая индексация `[]` не
поддерживает строки, а `len`/конкатенация не позволяют извлечь их байты.
UTF-8 не декодируется: `substr` может разрезать многобайтовый символ.
Unicode normalization/case folding, regex и сортировка строк не реализованы.

## random.luma

Генератор полностью написан на Luma: Park–Miller с методом Schrage. Промежуточные
целые значения точно представляются в существующем `double`. Период — 2147483646;
выход предсказуем и не пригоден для криптографии. По умолчанию seed равен `1`;
автоматического seed от часов/OS нет. Состояние общее для импортов одного модуля.

| API | Результат и ограничения |
| --- | --- |
| `random_seed(seed)` | Сбрасывает состояние; seed — целое число от `1` до `2147483646`; возвращает `nil`. |
| `random()` | Number в полуоткрытом диапазоне `[0,1)`. |
| `random_range(lower, upper)` | Равномерное целое number в **замкнутом** диапазоне. Границы целые, от `-2147483646` до `2147483646`, `lower <= upper`; число возможных результатов не более `2147483646`. Одинаковые границы допустимы. |

`random_range` отбрасывает неполный хвост перед взятием остатка. Недопустимые типы,
NaN/inf, неправильный seed и диапазон дают LumaError. Вспомогательная функция
`_random_next` и переменная `_random_state` — детали реализации.

## io.luma

| API | Результат и ограничения |
| --- | --- |
| `prompt(message)` | Печатает строковое приглашение с переводом строки, затем читает строку через `input()`. Пустой ввод → `""`, EOF → `nil`. |
| `read_number()` | Читает через `input()` и явно преобразует через `num()`. EOF → `nil`; пустая/некорректная строка → ошибка существующей `num()`. |

Обе функции написаны на Luma. `input`, `print`, `num` сохраняют прежнее поведение.
Поток ввода по-прежнему подменяется в тестах. Файловые операции не добавлены:
для демонстрации и консольных приложений достаточно существующего IO.

## Native primitives

Новые глобальные builtins:

| Функция | Назначение |
| --- | --- |
| `type(value)` | Возвращает `"nil"`, `"boolean"`, `"number"`, `"string"`, `"array"` или `"function"`; native и Luma-функции имеют один тип. |
| `assert(condition, message)` | Использует обычную truthiness Luma; при ложном условии бросает LumaError с указанной строкой сообщения. Message обязателен и должен быть строкой. При успехе возвращает `nil`. |
| `_luma_sqrt(value)` | Конечный неотрицательный number → number. |
| `_luma_pow(base, exponent)` | Конечные числа → конечный вещественный результат либо ошибка. |
| `_luma_slice(text, start, count)` | Проверяет типы/границы и извлекает байты строки. |

`type` нужен, в частности, чтобы различать `[]` и `""`: обе величины имеют длину
ноль, а непустые строки не индексируются. `assert` даёт библиотеке возможность
сообщать о доменных ошибках без нового синтаксиса исключений.

Имена этих builtins заняты в начальном глобальном окружении; старые программы,
объявлявшие такие глобальные имена, должны переименовать их или использовать
локальное теневание. Имена `_luma_*`, `_math_*`, `_string_*`, `_random_*`
зарезервированы соглашением для реализации библиотеки. Без импортов функции
`abs`, `find`, `random` и прочие публичные функции модулей не определены.

Всего: 19 публичных и 3 вспомогательные Luma-функции, 5 новых native builtins.
Три публичные Luma-функции (`pow`, `sqrt`, `substr`) являются тонкими обёртками.

## Пример

```luma
import "../stdlib/math.luma"
import "../stdlib/random.luma"
random_seed(123)
for i in 0..3 do
    print(clamp(random_range(-5,10),0,6))
end
```

Полная программа: [stdlib_demo.luma](../examples/stdlib_demo.luma). Ввод: имя героя и числовой seed.
## Практические примеры

Каждый пример ниже — отдельная программа, сохранённая в `examples/`.

### Математика

```luma
import "../stdlib/math.luma"
print(abs(-7), min(3,8), max(3,8), clamp(12,0,10))
print(pow(2,3), sqrt(16))
```

Результат: `7 3 8 10`, затем `8 4`.

### Строки

```luma
import "../stdlib/string.luma"
let text = trim("  Luma  ")
print(string_length(text), substr(text,0,2), find(text,"ma"))
print(contains(text,"um"), starts_with(text,"Lu"), ends_with(text,"ma"))
print(join(["hello",text], " "))
```

Результат: `4 Lu 2`, `true true true`, `hello Luma`.

### Воспроизводимый random

```luma
import "../stdlib/random.luma"
random_seed(123)
let first = random()
random_seed(123)
assert(first == random(), "same seed must reproduce the sequence")
print(random_range(1,6))
```

Одинаковые seed и последовательность вызовов дают одинаковый результат.
Разные `random_range` могут потреблять разное число внутренних samples.

### Консольный IO

<!-- luma-check: input Ada|21 -->
```luma
import "../stdlib/io.luma"
let name = prompt("Name?") or "Guest"
print("Hello, " .. name)
print("Age?")
let age = read_number()
if age != nil then print(age + 1) end
```

Ввод: `Ada`, затем `21`, на отдельных строках. Для принятия пробелов вокруг
числа явно используйте `num(trim(input()))` с проверкой EOF и импортом string.
`read_number` сам не обрезает пробелы, не ограничивает число конечными значениями
и сохраняет поведение [num](BUILTINS.md#num).

## Производительность и доступность

`find` делает последовательный поиск со срезами; `join` строит результат
повторной конкатенацией. Это простые реализации, не оптимизированные для очень
больших текстов. Строки и массивы не имеют общего лимита памяти.
Внутренние helpers технически доступны из общей области, но не являются
публичным API. Документация относится к runtime 0.2.0; совместимость с будущими
версиями не обещается. [Builtins](BUILTINS.md), [модель import](LANGUAGE.md#import).
