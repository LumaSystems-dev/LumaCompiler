# Руководство по Luma 0.2.0

Практическое руководство описывает текущую реализацию, а не планы.
[Индекс](README.md) · [Builtins](BUILTINS.md) · [Stdlib](STDLIB.md).
Каждый Luma-блок ниже — отдельный пример. Если он содержит import,
сохраните его в `examples/`, если не указано другое.

## 1. Основы

Программа — последовательность инструкций. Комментарий `#` идёт до конца строки.
Имена чувствительны к регистру; используйте ASCII-буквы, цифры и `_`,
не начиная с цифры. Ключевые слова не могут быть именами:

```text
and break by continue do else elseif end false for function if import in
let nil not or return then true while
```

`in` используется в числовом for, но не означает наличие foreach.
Пробелы и переносы строк незначимы; инструкции могут занимать несколько строк.
`;` необязателен. Пустые `;` поддержаны на верхнем уровне; внутри блока
не вставляйте отдельные пустые инструкции. Обычные вызовы и присваивания
могут завершаться `;`. После `let`, `return` и `break` внутри блока он
может остаться лишним токеном — в примерах блоков лучше обходиться без него.
Отдельным выражением-инструкцией может быть только вызов, не `x + 1`.

```luma
# Two statements on one line; multiline arithmetic.
let x = 2; print(x);
let total = (1 +
             3)
print(total)
```

Файл должен быть UTF-8 без BOM; строковые литералы могут содержать русский текст.
Нет одиночной точки, блочных комментариев или single-quoted строк.

## 2. Переменные и области видимости

`let name = expression` требует инициализатор. Присваивание использует `=`,
а сравнение `==`. Цепочки `a = b = 1` и операторы `+=` не поддержаны.

```luma
let x = 10
let name = "Ada"
x = x + 5
if true then
    let x = 99
    print(x)
end
print(x, name) # 15 Ada
```

Объявление должно предшествовать использованию. Повторное объявление в одной
области — ошибка; вложенная область может затенить внешнее имя.
Присваивание изменяет ближайшую найденную переменную и может менять её тип.
Ветки if, тела циклов и функций имеют области. На каждой итерации создаётся
новая область. Переменная for за пределами цикла недоступна.
Отдельного `do ... end`-блока вне цикла нет.

## 3. Значения и типы

| Тип / результат type | Создание | Свойства |
| --- | --- | --- |
| number | `10`, `12.5`, `-3` | Один тип C++ double, не отдельный integer |
| string | `"hello"` | Значение строки, операции над байтами |
| boolean | `true`, `false` | Сравнения и `not` возвращают boolean |
| nil | `nil` | Отсутствие значения; `null` не является литералом |
| array | `[]`, `[1,"x",nil]` | Изменяемый список, ссылочная семантика |
| function | Именованное объявление `function` | Функции можно хранить и передавать |

```luma
let value = nil
value = [1,"x",true]
print(type(value), type(value[0]), type(print)) # array number function
```

Числовые литералы: десятичные цифры с необязательной дробной частью после точки.
Нет hex, экспоненциального литерала `1e3`, формы `.5` или `5.`.
Для экспоненциального текста доступно `num("1e3")`.
Double не гарантирует точность произвольно больших целых и десятичных дробей.

## 4. Арифметика и приоритеты

Арифметика принимает только number: бинарные `+`, `-`, `*`, `/`, `%`
и унарный минус. Унарного плюса и оператора степени нет.
`%` вычисляется как `a - floor(a/b) * b`, знак остатка следует делителю.
Деление на ноль не бросает исключение: double даёт inf/nan; modulo нуля — nan.
Stdlib math, в отличие от базовой арифметики, отклоняет неконечные значения.

```luma
print(7 / 2, -7 % 3, 7 % -3) # 3.5 2 -2
print((2 + 3) * 4, -5)
```

От слабого к сильному:

| Уровень | Операторы | Ассоциативность |
| --- | --- | --- |
| 1 | or | Левая |
| 2 | and | Левая |
| 3 | not | Унарный |
| 4 | == != < <= > >= | Левая, один общий уровень |
| 5 | .. | Правая |
| 6 | + - | Левая |
| 7 | * / % | Левая |
| 8 | Унарный - | Унарный |
| 9 | Вызов () и индекс [] | Цепочки слева направо |

Скобки меняют порядок. `not a == b` означает `not (a == b)`.
`..` вне заголовка for — конкатенация, не самостоятельное range-значение.

## 5. Сравнения

`==` и `!=` допустимы для любых типов. Разные типы не равны.
Строки сравниваются по содержимому; массивы и функции — по идентичности,
а не глубокому содержимому. NaN не равен даже самому себе.
`<`, `<=`, `>`, `>=` принимают пару чисел либо пару строк;
строки упорядочиваются лексикографически по байтовому представлению.
Смешение типов в упорядоченном сравнении — ошибка.
Сравнения цепочкой не имеют математического смысла:
вместо `1 < x < 5` пишите `1 < x and x < 5`.

```luma
let a = [1,2]
let b = a
print(a == b, a == [1,2], 1 == "1") # true false false
print(2 <= 2, "abc" < "abd")
```

## 6. Логика

Ложны **только false и nil**. Ноль, пустая строка и пустой массив истинны.
`and` и `or` вычисляют правую часть только когда нужно и возвращают
значение выбранного операнда, а не обязательно boolean. `not` — boolean.

```luma
print(nil or "Guest", 0 or 99) # Guest 0
print(false and num("bad")) # false; conversion is not called
print(not "", not nil) # false true
```

Поэтому `input() or "Guest"` обрабатывает EOF, но не пустую строку.

## 7. Условия

```luma
let score = 85
if score >= 90 then
    print("excellent")
elseif score >= 70 then
    print("good")
else
    print("try again")
end
```

`then` и `end` обязательны; elseif/else необязательны.
Исполняется только первая истинная ветвь. Каждая ветвь имеет свою область.
Analyzer проверяет и неисполненные ветви.

## 8. Циклы

```luma
let n = 3
while n > 0 do
    print(n)
    n = n - 1
end
for i in 0..5 do
    if i == 2 then continue end
    if i == 4 then break end
    print(i) # 0, 1, 3
end
for j in 3..0 by -1 do
    print(j) # 3, 2, 1
end
```

Числовой for имеет полуоткрытые границы: начальная включена, конечная исключена.
Шаг по умолчанию 1; нулевой шаг — ошибка. Границы и шаг вычисляются один раз;
числа могут быть дробными. Используйте конечные числа и шаг, действительно
изменяющий счётчик, чтобы избежать зависания. Переприсваивание переменной
for в теле не меняет внутренний счётчик. `continue` выполняет инкремент.
Сложные выражения границ заключайте в скобки.
`break`/`continue` действуют на ближайший цикл и не пересекают функцию.
Foreach по массивам отсутствует — используйте `0..len(array)`.

## 9. Функции и замыкания

```luma
function add(a,b)
    return a + b
end
function apply(fn,a,b)
    return fn(a,b)
end
let operation = add
print(apply(operation,2,3)) # 5
```

Ровно указанное число параметров; нет default/variadic параметров.
Аргументы вычисляются слева направо. Обычные значения передаются как значения;
массивы сохраняют общую ссылку. Можно возвращать функции.
Вызов до объявления не разрешён; рекурсия самой функции разрешена.
Тело также анализируется до исполнения.

`return expression` завершает функцию. Если return отсутствует либо
не содержит выражения, результат nil. Перенос строки не ограничивает return:
следующий токен, способный начать выражение, будет его частью.
Чтобы вернуть отсутствие значения явно, пишите `return nil`.
Повторение имени параметра запрещено. Текущий Analyzer также отклоняет
`let` с именем параметра прямо в теле; используйте другое имя.

```luma
function makeCounter()
    let count = 0
    function next()
        count = count + 1
        return count
    end
    return next
end
let counter = makeCounter()
print(counter(), counter()) # 1 2
```

Замыкание хранит окружение определения, а не окружение вызова.
Разные вызовы makeCounter создают отдельное состояние.
Захват переменных циклов происходит по итерациям.
Анонимных function-выражений нет; вложенные именованные функции доступны.

## 10. Массивы

```luma
let numbers = [1,2,3]
print(numbers[0])
numbers[1] = 9
push(numbers,4)
let alias = numbers
alias[0] = 8
print(numbers) # [8, 9, 3, 4]
let matrix = [[1,2],[3,4]]
matrix[1][0] = 7
print(matrix[1][0]) # 7
let empty = []
print(len(empty)) # 0
```

Индекс — конечное number, `0 <= index < len(array)`. Отрицательные, NaN,
inf и значения вне диапазона дают ошибку. **Дробный индекс усекается** после
проверки: `[10,20][1.9]` возвращает 20. Для ясности используйте целые.
Присваивание не расширяет массив: для добавления есть push.
Элементы могут иметь разные типы; двумерность — вложенные массивы, не новый тип.
Массивы могут ссылаться на себя; печать обнаруживает цикл, но GC нет.
Не полагайтесь на порядок побочных эффектов при индексном присваивании:
интерпретатор вычисляет RHS перед целью, VM — цель перед RHS.

## 11. Строки

Только двойные кавычки. Escape-последовательности:
`\n`, `\t`, `\r`, `\\`, `\"`. Нет interpolation или многострочного литерала.
`..` соединяет строки и/или числа, в том числе два числа как текст.
Для других типов сначала используйте str. `+` не соединяет строки.

```luma
let name = "Luma"
print("Hello, " .. name .. "!")
print("line1\nline2")
print("flag=" .. str(true))
print(len("Лума")) # 8 bytes, not 4 characters
```

Строки не индексируются через `[]` и не изменяются по индексу.
Модуль string предоставляет срезы, поиск, trim и join.
Позиции/длины в байтах, поэтому substr может разрезать UTF-8-символ.
Unicode-aware индексации, normalization и case folding нет.

## 12. Импорты

<a id="import"></a>

```luma
import "lib/math.luma"
print(add(5,3), square(4), moduleTag)
```

Здесь используется существующий `examples/lib/math.luma`, **не stdlib math**.
Путь — только строковый литерал; для переносимых примеров используйте `/`.
Импорт разрешён только на верхнем уровне, не внутри функций/условий/циклов.
Относительный путь отсчитывается от файла с import. Например, import
`"ui.luma"` в `examples/rpg_adventure/lib/combat.luma` подключает соседний ui.
Вложенные импорты разворачиваются рекурсивно; их объявления вставляются на
месте import до Analyzer. Верхнеуровневые инструкции модулей выполняются
при исполнении объединённой программы, не во время compile.

Один canonical path подключается один раз в рамках одной компиляции.
`"lib/math.luma"` и `"./lib/math.luma"` дедуплицируются; разные файлы
с одинаковым содержимым остаются разными модулями.
Нормализация использует filesystem weakly_canonical; не обещается отдельная
регистронезависимая идентичность путей. Циклический импорт — ошибка с цепочкой.
Глубина цепочки ограничена 128 с учётом корневого файла.

Нет namespaces, exports, скрытых объявлений, автопоиска stdlib или package manager.
Имена модулей и программы разделяют глобальную область, порядок объявлений важен.
Конфликты имён — ошибки. Ошибки разбора и анализа импортов включают доступные
пути/контекст. Runtime-диагностика ещё не хранит полную карту происхождения модулей.
В `.lbc` уже содержится библиотечный код, но не исходные файлы.

## 13. Ошибки

Следующие фрагменты намеренно ошибочны.

<!-- luma-check: error -->
```luma
print(!true)
```

Lexer: `Unexpected character '!'`. Для отрицания используйте `not`.

<!-- luma-check: error -->
```luma
print(score)
```

Analyzer: `Unknown variable 'score'`. Объявите имя до использования.

<!-- luma-check: error -->
```luma
let x = ;
```

Parser: `expected expression but got ';'`. Добавьте инициализатор.

<!-- luma-check: error -->
```luma
print(1 + "bad")
```

Runtime: `cannot add number and string`. Выберите числа для арифметики,
либо `..` для текста.

<!-- luma-check: error -->
```luma
print([1][4])
```

Runtime: `array index 4 is out of bounds (length 1)`.
Арность известного вызова проверяет Analyzer; вызов через переменную — runtime.
Type checks в общем случае происходят во время исполнения.

<!-- luma-check: error -->
```luma
len()
```

Analyzer: `function 'len' expects 1 arguments, got 0`.
Передайте строку или массив; число аргументов не является optional.

<!-- luma-check: error -->
```luma
import "__missing_documentation_module__.luma"
```

ImportResolver: `imported file '...' not found (resolved to '...')`.
Проверьте файл и путь от импортирующего исходника, не от консоли.

Compiler также ограничивает размер конструкций: `too many bytecode constants`,
`too much code to jump over`, `loop body too large`.
Для слишком большой функции разделите код на меньшие функции/модули;
импорт сам по себе не устраняет все лимиты общего Chunk.

CLI печатает файл/строку и доступную байтовую колонку, затем
`Error at line N: ...`. Указатель не является Unicode-визуальной колонкой.
Путь/колонка доступны не для всех фаз. Артефакт хранит номера строк,
но не текст, колонки или полные пути импортированных модулей.
Ошибку языка нельзя перехватить try/catch внутри Luma.
Процесс возвращает 65; неправильный CLI-вызов — 64; недоступный
главный входной/выходной файл — 66. Отсутствующий импорт — 65.
Подробнее: [CLI](CLI.md), [Bytecode](BYTECODE.md), [архитектура](../DESIGN.md).
